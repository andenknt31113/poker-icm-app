### B. 作った理由から入る版

```
バブルのオールイン、コールしていいのか毎回「たぶん」で決めていたので、数字で確かめられるアプリを作っています。

今回の更新で、必要勝率を近似ではなく厳密なICM計算に変えました。局面によっては数ポイント変わります。

#ポーカー #ICM #個人開発
```

### C. 例題で見せる版（card-1 を添付）

```
残り4人・賞金 50/30/20。
自分はBBで4BB、SBが18BBからオールイン。

コールに必要な勝率は？

チップだけで考えると 28.6%。
ICM込みだと 33.5%。

この差がリスクプレミアムです。Poker ICM で自分の卓の数字を確かめられます。
```

数字はストア用スクショ（01-spot）と同じ局面のもの。

### D. Nash の紹介（card-2 を添付）

```
Poker ICM 1.4 では、Nashを全員ぶんの一覧表にしました。

「COが押す → BTN・SB・BBがそれぞれどこまでコールできるか」が1画面に並びます。コールが入ったあと、さらにもう1人がコールするレンジも出ます。
```

## おすすめの進め方

- **最初は A を固定ポストにする。** リンクは本文ではなくリプライに置く（リンク入りの投稿は表示が伸びにくいと言われているため。確かめた話ではない）。
- **C の例題型を続ける。** 告知は1回で流れるので、週に1〜2回「この局面、必要勝率は？」を出すほうがポーカー層に届きやすいと思う（推測）。局面を変えるだけで量産できる。
- **動画（promo-1.4.mp4）を A か C に付ける。** 画像カードと同じデザインで、機能を見出しつきで順に見せるもの。
- **無料で試せる範囲を伝える。** 例題と4人までの卓は無料で全機能を使える、と書くと入りやすい。
- **正確さの話は控えめに1回。** HRC の無料版と照合した、という話は刺さる人には刺さるが、照合した範囲（どの局面で、どれだけ一致したか）を添えて書く。
- **レビューのお願い。** 使ってくれた人に App Store の評価を頼む。評価が0件だと検索で埋もれやすい。
- **note 記事は後回しでいい。** 書くなら「近似と厳密 ICM で何ポイントずれるか」の実例が中身になる。
